# Voice Input Buddy (Windows) - 软件架构设计

Voice Input Buddy for Windows 是面向 Windows 10/11 的纯软件版硬件语音桥接工具。其目标是将闲置的蓝牙电视遥控器（如小米蓝牙遥控器、Google Chromecast 遥控器等）直接通过电脑自带蓝牙连接，将其打造成系统全局的“按住说话”语音输入按键，并将遥控器麦克风拾取的声音低延迟送入微信输入法、豆包输入法、Windows 11 自带语音听写等目标工具中。

本项目坚持**纯软件方案**，无需任何额外 USB 开发板或硬件接收器。

## 二、技术栈选型

本项目选用 **原生 Windows 技术栈（C# / .NET 8）** 进行开发：

| 层次 / 模块 | 选型 | 选用理由 |
| :--- | :--- | :--- |
| **运行时环境** | **.NET 8 (LTS)** | 现代化 C# 特性，高性能异步与内存操作（`Span<T>`、`Memory<T>`），支持 Native AOT 单文件发布。 |
| **UI 框架** | **WPF (配合 WPF-UI) 或 WinUI 3** | 原生 Windows 11 Fluent Design（支持 Mica 亚克力材质与系统暗黑模式），高 DPI 自适应，托盘与向导开发成熟。 |
| **蓝牙通信 (BLE)** | **WinRT API (`Windows.Devices.Bluetooth`)** | 微软官方第一方蓝牙栈，完整支持 GATT 服务发现、特征值写入与数据通知（Notification），与 Windows 蓝牙系统设置深度集成。 |
| **音频推流** | **NAudio (基于 WASAPI Render)** | 成熟的低延迟音频写入库，以独占/共享模式将解码后的 PCM 音频推入虚拟声卡端点。 |
| **音频解码** | **纯 C# 实现 IMA ADPCM 解码器** | 纯内存计算，结合 `Span<byte>` 与查表法，单核占用低于 0.1%，零外部非托管依赖。 |
| **虚拟麦克风** | **VB-CABLE (已获微软 WHQL 认证)** | 规避 Windows 内核驱动签名限制，利用成熟认证驱动，安装包内嵌静默安装脚本。 |
| **按键监控与注入** | **Win32 Raw Input + `SendInput`** | 监听遥控器全局 HID 报文，亚毫秒级注入目标输入法的触发快捷键（如 `Ctrl + Shift + V`、`Win + H` 等）。 |
| **打包与安装** | **Inno Setup** | 单个 EXE 安装包，内嵌驱动一键静默安装与卸载清理，轻量无冗余。 |

## 三、核心模块与分层设计

应用整体采用 MVVM 架构，业务引擎与 UI 解耦，核心分为以下 5 个逻辑层：

```text
VoiceInputBuddy.sln
├── src/VoiceInputBuddy.Core/             # 纯业务核心库 (无 UI 依赖)
│   ├── Bluetooth/                        # WinRT BLE 连接、扫描、重连与保活
│   ├── Protocols/                        # ATVV 协议、G9N9N / 小米设备报文协议
│   ├── Audio/                            # ADPCM 解码、音频环形缓冲区、WASAPI 输出
│   ├── Input/                            # 按键捕获、手势识别、SendInput 键盘注入
│   └── Config/                           # 用户设置持久化 (JSON)
│
├── src/VoiceInputBuddy.App/              # 桌面客户端 (WPF / WinUI 3)
│   ├── Views/                            # 主界面、设置向导、按键映射视图、关于窗口
│   ├── ViewModels/                       # MVVM 视图模型
│   ├── Tray/                             # 系统托盘图标、上下文菜单、后台运行管理
│   └── Services/                         # 驱动检测、自启动管理、更新检查服务
│
└── src/VoiceInputBuddy.Installer/        # Inno Setup 脚本与驱动打包资源
```

### 1. Bluetooth & Protocol Runtime
* **职责**：维护与目标遥控器的 BLE 连接状态。
* **状态机**：`Disconnected` -> `Connecting` -> `ServicesDiscovered` -> `Ready`。
* **特性**：
  * 支持自动重连（遥控器休眠唤醒后自动恢复）；
  * 具备超时看门狗，防止蓝牙通道静默断开。

### 2. Audio Pipeline & Ring Buffer
* **职责**：接收遥控器上报的语音分包，解码为标准音频，送入输出缓冲区。
* **低延迟保证**：采用线程安全的无锁环形缓冲区（`CircularBuffer`），容量控制在 100~200ms，防止网络波动或时钟漂移导致的杂音或累积延迟。
* **格式规范**：统一解码为 `16,000 Hz, 16-bit Signed Integer, Mono (单声道)`。

### 3. Voice Session Coordinator (会话编排器)
* **职责**：统一编排“按下说话”、“松开结束”的生命周期。
* **时序要求**：
  1. 监听到遥控器语音键按下；
  2. 向目标输入法注入语音触发快捷键（或激活系统听写）；
  3. 启动 BLE 语音采集握手（发送 `MicrophoneOpen` 指令）；
  4. 开启 WASAPI 实时推流；
  5. 监听到语音键松开，发送 `MicrophoneClose` 指令，补齐尾帧并停止注入。

## 四、线程模型与并发隔离

为了杜绝 UI 卡顿与音频断续（Glitch），系统划分清晰的线程职责：

1. **UI 线程 (Main Thread)**：仅负责 WPF 界面渲染、向导动画与用户交互响应。
2. **BLE 事件回调队列 (WinRT ThreadPool)**：异步处理 GATT Notification 数据，接收 ADPCM 包后立即移交音频处理管线。
3. **音频解码与推流线程 (Dedicated High-Priority Thread)**：专有高优先级线程，负责 ADPCM 解码与 WASAPI 缓冲泵（Pump），确保音频流不被主线程操作阻塞。
4. **低级按键钩子线程 (Input Hook Loop)**：维持 Win32 消息循环，捕获原始按键事件并进行防抖判定。
