# 开发路线图与里程碑 (Development Roadmap)

本文档规划了 `voice-input-buddy-windows` 从核心链路验证到正式发布的阶段性里程碑与验收门槛。

---

## 一、阶段规划与门槛把控

为避免过早陷入 UI 与安装包细节而掩盖底层协议风险，本项目设立**严格的第一阶段验收门槛（Phase 1 Acceptance Gate）**：

```text
┌─────────────────────────┐       ┌─────────────────────────┐       ┌─────────────────────────┐
│         Phase 1         │       │         Phase 2         │       │         Phase 3         │
│   核心链路 PoC 与验收门槛 │  ──>  │   原生 WPF 客户端与向导  │  ──>  │    安装包制作与正式发布   │
└─────────────────────────┘       └─────────────────────────┘       └─────────────────────────┘
 (真机跑通全链路，转写成功)          (自包含 Fluent 界面与托盘)         (Inno Setup + 驱动指引)
```

> [!IMPORTANT]
> **第一阶段真机验收门槛 (Phase 1 Acceptance Gate)**：
> 必须在指定型号和固件（小米 RC001/RC003 或 Google G9N9N）上，在 Windows 物理机（内置蓝牙）通过公开 API 完成以下验收标准后，方可启动 Phase 2 的 UI 和安装包开发：
> 1. **HID 与 GATT 共存**：按键与语音流互不冲突，无驱动级通信挂起；
> 2. **清晰拾音**：16kHz 录音无白噪声、杂音或啸叫（验证 `AUDIO_SYNC` 校准）；
> 3. **首尾音完整**：Command Pre-roll 与 Drain 机制生效，首字不吞、尾句不截断；
> 4. **长按保活**：连续说话超过 20 秒不发生掉流（验证 `MIC_EXTEND` 握手）；
> 5. **休眠与唤醒重连**：遥控器休眠后再次按下能自动重新建立会话；
> 6. **真实输入法转写验收**：至少在一个真实目标工具（如微信输入法或豆包）中实际转写出正确的中文句子。

---

## 二、详细里程碑划分

### Milestone 1: 核心音频与协议链路 PoC (Console / CLI)
**目标**：脱离复杂 UI，在纯 C# 控制台环境下跨越上述 Phase 1 验收门槛。

- [ ] **技术基线搭建**：
  - 创建 `.NET 10 LTS` 控制台解决方案；
  - 引入 `NAudio`（WASAPI 支持）；
- [ ] **WinRT 蓝牙通信实现**：
  - 调用 `Windows.Devices.Bluetooth` 扫描并配对小米/Chromecast 遥控器；
  - 订阅 `AB5E0001` 主服务下的 `Audio` (0003) 和 `Control` (0004) 特征值；
- [ ] **ATVV 完整状态机与 ADPCM 解码**：
  - 处理 `0x0B (CAPS)`、`0x08 (START_SEARCH)`、`0x04 (AUDIO_START)`、`0x00 (AUDIO_STOP)`；
  - 正确提取并传递动态 `SessionID`，实现 `0x0D (MIC_CLOSE)` 与 `0x0E (MIC_EXTEND)`；
  - 解析 `0x0A (AUDIO_SYNC)` 并同步 `ImaAdpcmDecoder` 的 Predictor 和 StepIndex；
- [ ] **WASAPI 音频推流引擎**：
  - 打开已安装好的 VB-CABLE "CABLE Input" 端点，以 16kHz 16-bit Mono 实时泵入音频；
- [ ] **时序编排与 SendInput 注入**：
  - 编写 40 字节（x64）对齐的 `SendInput` 模块，处理 Pre-roll 首音缓冲与 Drain 尾音排空；
  - 在记事本中配合微信输入法完成端到端中文语音转写验收。

---

### Milestone 2: Windows 原生客户端与设置向导 (Desktop GUI)
**目标**：采用成熟的 WPF 框架构建 Windows 11 Fluent 风格客户端，重点补齐目标工具的麦克风配置引导。

- [ ] **WPF (.NET 10 LTS) 架构落地**：
  - 采用 `CommunityToolkit.Mvvm` 与 `WPF-UI`；
  - 配置**自包含单文件发布（Self-Contained Single-File）**，撤回通用 Native AOT 承诺（WPF 默认不支持裁剪）；
- [ ] **闭环式新手设置向导 (Setup Wizard)**：
  1. **驱动检查与引导**：检测 CABLE Input 真实可用性，若缺少则展示官方许可声明并引导从官网下载，提示用户安装后可能需要重启；
  2. **设备配对**：列出系统已配对的蓝牙遥控器，展示连接状态；
  3. **本程序拾音测试**：遥控器开麦测试，界面实时呈现 VU 音量跳动与波形；
  4. **目标输入工具麦克风配置引导**：
     * **微信输入法**：引导在设置中将语音麦克风指定为 `CABLE Output`；
     * **豆包输入法**：引导在设置中将麦克风指定为 `CABLE Output`；
     * **Windows 11 自带听写 (`Win + H`)**：说明其严格跟随“系统默认录音设备”，指导用户如何设置系统默认输入设备，并说明对其他会议软件的影响；
  5. **实际转写验收**：向导提供一个测试输入框，要求用户按住遥控器说出一段指定文字，当文本框成功转写出文字后，向导才允许“完成”，确保音频链路真实打通；
- [ ] **系统托盘与自启动**：
  - 关闭窗口最小化至托盘，支持开机静默后台启动。

---

### Milestone 3: 按键映射引擎与增强特性
**目标**：在完成语音核心链路的基础上，探索普通按键的重映射与常用语。

- [ ] **Raw Input 全局按键监听器**：
  - 监听 Consumer Control 报文，区分遥控器与主键盘；
  - 默认提供 Level 2 附加映射（例如非语音按键映射为常用短语或快捷键）；
- [ ] **PoC 预研：Level 3 替换屏蔽原始按键**：
  - 在真实硬件上测试是否能可靠拦截特定遥控器按键而不误伤主键盘；
- [ ] **Unicode 常用语上屏**：
  - 使用 `KEYEVENTF_UNICODE` 注入预设文本，中英文混写零乱码。

---

### Milestone 4: 安装包封装与 CI/CD 自动化构建
**目标**：提供标准的 Windows 安装程序。

- [ ] **Inno Setup 脚本**：
  - 打包自包含的 .NET 10 主程序；
  - 不私自捆绑闭源驱动，若检测到缺少驱动则弹出官方下载提示；
- [ ] **GitHub Actions 工作流 (`.github/workflows/build.yml`)**：
  - `windows-latest` 环境编译自包含单文件二进制，生成 Release 产物。
